Three Maximum-Severity Flaws in the Platform Your Client’s HR Data Sits On — Patched Thursday, Unauthenticated, No User Interaction
BREAKING ServiceNow Security
ServiceNow published its August CVE advisory on Thursday 27 August covering four vulnerabilities in the AI Platform, three of them scoring a straight 10.0. CVE-2026-18885 is a code injection flaw in the GraphQL Composite Data API allowing arbitrary code execution and access to or modification of instance data. CVE-2026-18886 is an improper access control weakness in the system configuration image upload processor leading to privilege escalation. CVE-2026-74820 is SQL injection reached through a dynamic schema ORDER BY clause. All three are exploitable by an unauthenticated attacker in a low-complexity attack with no user interaction required. A fourth, CVE-2026-6876, is a sandbox escape at 8.7. ServiceNow says it is not aware of malicious exploitation, which is a statement about today rather than a forecast — in July, Defused reported attackers actively exploiting CVE-2026-6875, a pre-auth sandbox escape in the same platform, and ServiceNow privately disclosed a separate incident last month in which an unauthenticated API endpoint was used to query data from customer instances. So what for a Deloitte HRSD consultant: this is not the platform team’s problem to own alone, because HRSD instances hold the highest-sensitivity data in the enterprise — grievance and investigation cases, medical and accommodation records, remuneration, termination files — and an unauthenticated SQL injection does not respect User Criteria, COE security policies or any HR-specific control you have configured. Three things worth doing on Monday. Establish patch currency for every client instance against the remediated builds (Xanadu Patch 11 Hot Fix 7a; Yokohama Patch 12 Hot Fix 3b and Patch 13 Hot Fix 4; the Zurich chain through Patch 12; Australia Patches 2 through 5), and treat sub-production as in scope because it usually holds a production clone. Ask the harder question of whether HR data is present in instances nobody counts as HR instances. And note the pattern rather than the individual bugs: three max-severity unauthenticated flaws in one advisory, in a platform whose GA MCP surface now exposes HR tools to external clients, means the security posture of the instance is now an HRSD design input, not a separate workstream.

Workday Put a Number on HR AI Adoption — a Quarter of New Contract Value, and 5,500 Customers Running Agents
HOT HR Tech
Workday reported fiscal 2027 second-quarter results on 27 August: total revenue US$2.649B up 12.8%, subscription revenue US$2.471B up 13.9%, operating margin improved to 11.8% of revenues from 10.6%. The line that matters for anyone selling HR transformation is underneath the headline. Set that beside ServiceNow’s AI annual contract value passing US$1B in July and the picture is consistent: two rival HR platforms independently reporting that AI has moved from pilot line item to a quarter or more of what customers are newly signing. So what for a Deloitte HRSD consultant: the objection has changed shape. Twelve months ago the hard conversation was whether HR AI was real; the numbers now answer that, and the hard conversation becomes whether the client’s own deployment is producing anything comparable. That is a much better problem for a consultant to have and a much worse one to be unprepared for, because the first question after “everyone is buying this” is “what did ours return”. Most HRSD agent pilots cannot answer it, because nobody captured a pre-agent baseline for handle time, first-contact resolution, deflection or case reopen rate. Capture the baseline before the pilot, not after. And be careful with the vendor numbers in a client room — ACV and ARR describe what customers bought, not what it delivered, and treating a sales metric as an outcome metric is exactly the move a sceptical CFO is waiting for.

NowLLM Is Finished — Every Out-of-the-Box HR Skill Is Quietly Moving to Someone Else’s Model
ServiceNow Governance
ServiceNow has closed its in-house model era. From 9 July, third-party model providers began rolling out as the default for out-of-the-box Now Assist skills and AI agents, with Google Gemini 3.5 Flash, OpenAI GPT 5.1 and GPT 5.4 Mini joining the existing Azure OpenAI, AWS Claude and Google Gemini options, and Now LLM is no longer the default for any AI skill or agent on the platform. The developer blog marking the end of NowLLM is unsentimental about why: renting frontier capability beats maintaining a proprietary model that trails it. The operationally important detail is buried in the rollout mechanics — the switch is tied to individual store app release schedules, so different products flip at different times, and if you have already configured a model provider your configuration is preserved. So what for a Deloitte HRSD consultant: this is a data-flow change disguised as a product update. A client whose privacy impact assessment says HR case summarisation runs on a ServiceNow-hosted model may now be running it on Gemini or GPT without anyone re-papering anything, because the default moved underneath them on a per-app schedule nobody was tracking. Three practical consequences. Build a model-provenance register that names, per Now Assist skill in use, which provider and which region now serves it and when that app made the switch. Re-check the DPIA and any data residency commitment against the answer rather than against last year’s architecture diagram. And treat explicit model configuration as the safe default on regulated engagements, because a preserved configuration is the only thing that stops the platform from choosing for you.

Moveworks Turned the Assistant Into an API and an MCP Client in the Same Month
NEW Agentic
Moveworks put both MCP Workspace and the Conversations API into Controlled Availability this month, alongside expanded admin visibility, improved document understanding and a Unified Analytics Dashboard. The two capabilities point in opposite directions and that is the interesting part. MCP Workspace is where an Agent Studio admin connects and governs MCP servers, with the MCP client discovering and calling those servers’ tools inside a conversation using the user’s own credentials in the upstream system — the assistant reaching outward. The Conversations API lets you drive the Moveworks assistant from your own application or route it through another orchestrator entirely — the assistant being reached inward. Note the credential model, because it is the design decision worth copying: per-user credentials in the upstream system, not a shared service account. So what for a Deloitte HRSD consultant: the assistant has stopped being a chat window and become a component, and that changes the architecture conversation on any client running Moveworks alongside or inside a ServiceNow estate. If the assistant can be called by another orchestrator, the question of which system owns the employee conversation is now a genuine design choice rather than a product default, and it has consequences for case-record fidelity, audit trail and where the entitlement decision actually gets made. Worth mapping, for each client, every path an employee request can take to an HR outcome and confirming that each one produces the same case record. Controlled Availability also means access is gated — if this matters to a live engagement, get the client into the programme now rather than waiting for GA.

The EU Split Its HR AI Rulebook in Two — Transparency Is Live Now, High-Risk Waits Until December 2027
WATCH Regulation
Four weeks on from the 2 August milestone, the shape of the EU AI Act for HR is clear and it is not what most compliance plans assumed. Article 50 transparency obligations are in force now: disclosure when a person is interacting with an AI system, machine-readable marking of synthetic content, deepfake disclosure, with penalties reaching €15M or 3% of worldwide annual turnover. The Annex III high-risk obligations — the ones covering systems used to make decisions about employment terms, promotion, termination, task allocation and monitoring or evaluating worker performance, which is to say most of what an HR AI programme actually does — were deferred to 2 December 2027 under the Digital Omnibus agreed between the Council and Parliament, with AI embedded in Annex I regulated products pushed to 2 August 2028. So what for a Deloitte HRSD consultant: resist the obvious client reading, which is that HR AI compliance has been postponed by sixteen months. Two things argue against it. The obligations that landed are precisely the ones that touch every conversational HR surface a client has already deployed, and they are testable today by anyone who opens the portal. And the deferral buys preparation time for requirements that have not changed in substance — risk management systems, data governance, technical documentation, logging, human oversight and conformity assessment still arrive, on a date now far enough away that it will fall off the roadmap and come back as an emergency. The useful framing for a client is that the deadline moved and the work did not. Build the artefacts on the original schedule and you are early rather than late; a decision record with inputs, model version, rationale and a named human reviewer serves the EU requirement and the converging Australian instruments at the same time.

BREAKING Infrastructure
NVIDIA reported second-quarter fiscal 2027 results on 26 August: revenue of US$96.2B for the quarter ended 26 July, up 18% sequentially and 106% year on year, with data centre revenue of US$89.0B up 117% and ahead of the US$86.33B consensus. Two implications worth carrying into client conversations. A three-year total cost of ownership model for an HR agent deployment, built on today’s per-token pricing, is almost certainly wrong in the client’s favour — which is a pleasant error, but it means a business case that only just clears the hurdle rate today is more robust than it looks. And the corollary is the one clients miss: if inference keeps getting cheaper, the binding constraint on HR AI value stops being model cost and becomes data quality, process design and change adoption, none of which get cheaper on NVIDIA’s schedule.

NEW Infrastructure

Stripe Paid US$7B for the Layer That Chooses Your Model — Because Routing Is Where the Money Is
HOT M&A
Stripe finalised an agreement to acquire OpenRouter for more than US$7B, reported by Bloomberg on 16 August. OpenRouter builds no models. It provides a single connection point to more than 400 models from over 60 companies including OpenAI, Anthropic, Google, Meta and DeepSeek, and decides which one should answer each request. The price is 5.4× the US$1.3B valuation the company carried at its Series B just three months earlier, and the buyer is a payments company — which tells you what the thesis is. Model routing and usage-based billing are the same problem viewed from two ends, and whoever owns the routing layer owns the metering, the attribution and the invoice. So what for a Deloitte HRSD consultant: the market has just valued the abstraction layer at seven billion dollars, which is a fairly loud argument for building one. Any HR AI architecture that names a specific model inside a Now Assist skill configuration, an Integration Hub spoke, a script include or a custom MCP server has hard-coded a decision that the rest of the industry is busy making soft. The advice to clients is unchanged but now considerably better supported: put model selection behind a routing layer with per-task policy, cost ceilings and fallback, so that switching providers is a configuration change rather than a project. The second-order point is commercial. If routing and billing consolidate, the enterprise buying pattern for AI shifts from per-vendor contracts to metered spend across many, and the client’s procurement and FinOps functions are not currently set up for that.

NVIDIA Agreed to Guarantee the Value of Its Own Chips as Collateral in a US$500B Financing Plan
WATCH Infrastructure
On 13 August, NVIDIA announced that Apollo, BlackRock, Blackstone, Brookfield, Goldman Sachs and KKR were willing to commit up to US$500B to build AI data centres — with NVIDIA agreeing to guarantee, with its own money, that its chips used as collateral in those deals retain their value. The structure is doing something specific. Lenders will not underwrite depreciating hardware they cannot price at the end of a term, so the manufacturer underwrites the residual value itself, and the financing unlocks. It is a defensible piece of engineering and it is also circular in a way worth naming: the party whose revenue depends on the build-out is guaranteeing the collateral that funds it. So what for a Deloitte HRSD consultant: this is not a story about HR, it is a story about the durability of the assumptions in every HR AI roadmap that runs past 2028. Client roadmaps now routinely assume compute keeps getting cheaper and more available indefinitely, and that assumption is increasingly underwritten by financial structures rather than by physics. That does not mean it breaks. It does mean a multi-year HR AI programme should carry an explicit dependency on external compute economics in its risk register rather than treating cheap inference as a law of nature — alongside the model-deprecation and pricing-change risks this digest has tracked all year. If you write risk registers for clients, this belongs in them, phrased plainly, with a review date.

The HR Blast-Radius Assessment — What an Unauthenticated Flaw Actually Reaches Inside an HRSD Estate
Three CVSS 10.0 vulnerabilities were patched on 27 August, all exploitable without authentication and without user interaction, one of them SQL injection against the instance database. Every HR control a consultant configures — User Criteria, COE security policies, HR profile access, encrypted fields — sits above the layer those flaws operate at, and none of it applies. Clients will ask their platform team whether they are patched. Almost nobody will ask the question that matters more to an HR director, which is what would have been reachable if they were not. Build the assessment that answers it. Stand up a Zurich sub-production instance loaded with realistic HR data shapes: grievance and investigation cases with attachments, medical and workplace-adjustment records, remuneration and termination files, background-check outcomes, and the HR profile tables that quietly join to everything. Map, table by table, what an unauthenticated database-level read would expose and how that maps to notifiable data breach thresholds under the Privacy Act, then do the same for an authenticated low-privilege account after a successful privilege escalation, so the client sees two distinct blast radii rather than one. Layer in the surfaces that have grown this year: the GA MCP server exposing HR tools to external clients, integration accounts, sub-production clones of production data, and any instance the HR team does not think of as an HR instance. Then produce three artefacts a client can act on — a patch-currency register per instance against the remediated builds, a data-exposure map keyed to breach-notification obligations, and a one-page HR-specific instance hardening checklist. Flagship because the advisory is days old, because the DeepSeek CVE-rediscovery result in this same issue says the patch-to-exploit window is compressing, and because “here is precisely what your HR estate exposes and here is your patch currency” is a conversation no HRSD competitor is currently having.

The Model-Provenance Register — Because the Model Behind Every OOTB HR Skill Changed and Nobody Was Told
Now LLM is no longer the default for any AI skill or agent on the platform. Since 9 July, third-party providers have been rolling out as the default for out-of-the-box Now Assist skills, tied to individual store app release schedules, which means different HR skills switched on different dates with no single announcement anyone can point to. A client whose privacy impact assessment describes HR case summarisation running on a ServiceNow-hosted model may now be sending that content to Gemini or GPT, in a region nobody has confirmed, against documentation nobody has updated. Build the register that closes the gap. Start with discovery: enumerate every Now Assist skill and AI agent active in a client instance, and for each one record the current model provider, the model version, the serving region, whether the configuration is explicit or inherited from the shifting default, and the store app release that moved it. Then build the evidence layer — a scheduled job that snapshots the provider configuration and flags drift, so the register stays true after the first pass rather than becoming a point-in-time artefact like every other compliance spreadsheet. Wire the output into three deliverables: a DPIA delta showing where documented data flows diverge from actual ones, a residency attestation pack for APRA-regulated and public-sector clients naming where each HR inference is served, and a configuration standard that pins providers explicitly on regulated engagements so the platform never chooses on the client’s behalf. Flagship because it is genuinely unglamorous work that nobody has done, because the divergence between documented and actual data flows is the exact finding a privacy regulator or an internal audit function surfaces, and because a firm that can produce a current, evidenced answer to “which model just processed that grievance case” is holding something clients cannot easily buy elsewhere.

The Agent Baseline Harness — Capture the Before, Because Every Client Is About to Ask What Theirs Returned
Workday reported AI driving more than a quarter of new ACV with 5,500 customers running agents; ServiceNow passed US$1B in AI annual contract value in July. Those numbers will be in front of every HR executive within a month, and the question that follows is not whether to buy but what the thing they already bought delivered. Most HRSD agent pilots cannot answer it, for a boring reason: nobody captured the pre-agent baseline, and reconstructing it after deployment is either impossible or unconvincing. Build the harness that fixes it, and make it something a practitioner can deploy in an afternoon at the start of an engagement rather than a bespoke analytics project at the end. Define the measurement set first and defend each metric — handle time by case type, first-contact resolution, deflection rate at the portal and assistant layers, escalation and reassignment counts, case reopen rate, time-to-first-response, and a sentiment or CSAT proxy where the client has one. Build it as a scoped app that snapshots those measures over a defined pre-deployment window, holds the baseline immutable, and then reports post-deployment deltas with confidence intervals and explicit seasonality adjustment, because HR case volumes are strongly seasonal and an unadjusted comparison against performance-review season will produce a result the client’s finance function will correctly refuse to believe. Add the cost side to make it a genuine return calculation: token consumption per completed business outcome rather than per conversation, which is the measure the agentic workload shape actually demands. Deliver a baseline capture app, a reporting pack, and a short methodology note explaining what the harness can and cannot attribute to the agent. Flagship because it converts a vendor sales metric into a client outcome metric, because the window to capture a baseline closes the moment the agent goes live, and because “we measured yours properly” is a durable differentiator in a market about to fill with unfalsifiable ROI claims.

HRSD MCP Server Permission Red-Team

Idea

Prove whether knowledge-base User Criteria and COE security actually survive the hop when an external MCP client calls HRSD instead of a browser session.

Advanced ServiceNow HRSD · MCP Server Console · Zurich New Added 22 Aug 2026

Hypothesis

A default HRSD MCP Server deployment using a shared service-account OAuth token collapses every knowledge-base User Criteria rule on the instance into a single omniscient identity, returning articles to callers who could never reach them through Employee Center — and per-user OAuth is the only configuration in which entitlements and the audit trail both survive the hop.

Approach

  1. Stand up the HRSD MCP Server in a Zurich sub-production instance via MCP Server Console, with HR Knowledge Search enabled.
  2. Seed a three-tier knowledge base: public articles, manager-only articles, and a genuinely sensitive tier scoped by User Criteria to a handful of HR partners (redundancy consultation, investigation procedure, executive remuneration).
  3. Create four test identities — general employee, people leader, HR partner, contractor — and a fixed set of twelve probe questions spanning all three tiers.
  4. Run the same twelve questions through four paths and diff the responses: Employee Center directly; MCP with per-user OAuth; MCP with a shared service-account token; and MCP called via a third-party client (Claude, Copilot Studio).
  5. Repeat against COE-secured HR case data to test whether case-level security policies hold when the request never touches the portal.
  6. Build the remediation: reference configuration, an audit pattern where the trail names a person rather than a service account, and a pre-enablement checklist.

Deliverables

Findings report with the four-path response diff and any entitlement leakage evidenced; reference secure configuration; audit and identity-propagation pattern; one-page pre-enablement checklist for platform teams; short executive briefing on the change to the HR knowledge security boundary.

Client fit

Any client on Now Assist or an AI Native SKU where MCP Server Console is included, particularly those with genuinely tiered HR knowledge (investigations, restructures, remuneration) and any client whose platform team is enthusiastic about connecting external AI clients to HRSD.

Effort & prerequisites

5–7 days, two practitioners (one HRSD/knowledge, one identity/integration). Requires a Zurich HRSD sandbox with MCP Server Console enabled, an OAuth-capable test identity provider, and at least one external MCP client.

Success signal

A reproducible, evidenced answer to whether User Criteria holds under each configuration, plus a reference configuration that demonstrably preserves entitlements and names a real person in every audit record.

MCP 2026-07-28 Migration & Governance Pack for HRSD

Idea

Inventory every MCP surface pointing into a client’s HRSD estate, score it against Tuesday’s stateless spec, and ship the reference migration and governance pattern.

Advanced ServiceNow HRSD · MCP · AI Control Tower Added 1 Aug 2026

Hypothesis

Most client HRSD estates already carry more MCP surface area than anyone has inventoried — a GA ServiceNow MCP Server Console plus custom HR servers plus several connected clients — and a repeatable discovery-and-scoring pass against the 2026-07-28 specification produces a migration register credible enough to fund a governance workstream, before the twelve-month deprecation window closes.

Approach

  1. Build a discovery method and script that enumerates MCP surfaces in a reference tenant: ServiceNow MCP Server Console instances, custom HR MCP servers, and connected clients (Moveworks, Copilot Studio, Claude, AWS Bedrock, bespoke agents).
  2. Score each surface against the new spec: stateful assumptions, sticky-session or shared-session-store dependencies, authorisation not on production OAuth 2.0 / OIDC, uncached tool-list calls, use of features now on the deprecation path.
  3. Stand up a reference stateless HR MCP server behind a plain round-robin load balancer with header-based routing, and wire role-based tool packages plus AI Control Tower audit trails end to end.
  4. Prove enterprise identity integration against Entra or Okta without the workarounds the old spec required, and capture the evidence an audit committee would ask for.
  5. Package the register template, scoring rubric, migration runbook and governance pattern for reuse across engagements.

Deliverables

MCP surface discovery script, migration register template with scoring rubric, working stateless reference server, governance and audit pattern, migration runbook, and a short executive briefing on the deprecation timeline.

Client fit

Any client running Now Assist or an AI Native SKU (MCP Server Console is included), clients with custom-built HR MCP servers, and multi-agent estates where more than one AI client reaches into HRSD.

Effort & prerequisites

8–10 days, two practitioners (one integration/identity, one HRSD). Requires a Zurich HRSD sandbox with MCP Server Console enabled and access to a test identity provider.

Success signal

A completed register for one real client estate that names specific surfaces needing migration with dates attached, plus a stateless reference server passing an identity and audit review.
